# Builder native restricted execution — ENG-1183 specification

Date: 2026-10-09. Status: executable backend specification against released source `30976670111b055e753dc8452ee1686faa90fe5d`. ENG-1178 is released and verified. User authorized ordered backend implementation, independent review, local/Dev E2E, source push, Dev deployment and Linear evidence comments. Frontend tickets wait until ALL six backend tickets and APIs are verified in Dev; no frontend implementation. ENG-1177 resource search remains paused.

## Intent and scope

The user authorized backend work on PRD gaps with subagents; frontend work is record-only. PRD §9.1 requires default Mock/Dry Run, separate confirmation identifying actual account and target before real effects, and no destructive execution. §10.1 permits generating Code, templates, HTTP, models and New Agent references; generation permission does not authorize their runtime effects. Preserve native execution and immutable historical Run/publication records.

The smallest defensible release is **restricted native Workflow execution**, not completion of PRD default Mock/Dry Run. Native Start/End graphs execute real computation. A typed HTTP response fixture adapter exercises the actual native HTTP node and downstream selectors without contacting the target. Code/template are a separately gated increment, described concretely below. Common Code workflows and most generated model/Agent workflows remain blocked until their owners gain safe capabilities. Neither input mocks nor HTTP fixtures prove business acceptance, provider permission, model quality or real effect success.

This document fixes conservative defaults rather than asking again for authorization. Root owns sequential subagent implementation and release gates. ENG-1183 includes both the restricted native surface and useful verified Code/template execution; neither a scalar demonstration nor disabled adapters alone close this ticket.

## Options considered

1. **Recommended: Dify-owned admission plus native factory/protocol capabilities.** Use the production service/generator/runner/GraphEngine and exact concrete node implementations. Restricted effects are enforced at their dependency boundary, with independent durable observations. All required interfaces exist in Graphon 0.7.0; initial implementation is source-local.
2. **Production mock node classes or a second executor.** Reject: replacement nodes bypass native validation/output shaping and produce weak evidence; a second executor duplicates ownership.
3. **Observer-layer blocking or node-type allowlists.** Reject as enforcement: Graphon swallows hook exceptions, labels do not establish capabilities, and constructors/pre-graph behavior can have effects before hooks.

## Release A: exact supported surface

Only standard `AppMode.WORKFLOW`, in-process full-graph Builder tests with scalar Start inputs and linear graph chains are admitted. Root is Start v1 and terminal is End v1. Supported intermediate implementations are native HttpRequest v1; Code v1 and TemplateTransform v1 remain denied until Release B is enabled. The concrete class objects imported from Graphon, explicit versions and validated configuration form the registry; aliases resolving to an unreviewed class/version fail closed. Missing version resolves through the normal native resolver, then must match the audited concrete implementation. No permissive default or generic “local node” class. Raw metadata refusal is conservative: an unused benign environment variable, configured external tracing, or an unreachable effectful node can block the entire test. This does not classify local DB reads as external effects. Relaxing each refusal requires an audited owner adapter (nonsecret scoped variable loading, explicit trace egress policy, or reached-node capability enforcement respectively).

A linear graph has exactly one Start, one End, no container parent/iteration/loop metadata, no cycles, one outgoing edge per nonterminal node and one incoming edge per nonroot node, and all graph nodes lie on that chain. This deliberately excludes branch/parallel/container coverage, even unreachable unsupported nodes. Native HTTP error defaults may still allow End success; installed Graphon0.7 emits GraphRunPartialSucceededEvent(exceptions_count=1) for the denied default-output path. Preserve that actual partial status and blocked receipts; End outputs never clear safety denial.

Reject before generation: Chatflow (all configurations), Agent app modes, trigger/snippet roots, resume/single-node/Celery variants, file inputs or file Start fields, environment/conversation variables, app external tracing, and enabled workflow features outside the reviewed scalar baseline. Feature admission recognizes the actual WorkflowAppConfig schema: empty/disabled defaults are accepted, unknown enabled entries and nonempty external-data settings are rejected. Never silently switch a feature off. Built-in platform DB/Redis, native Run persistence, configured platform telemetry and approved internal sandbox RPC are the infrastructure boundary; the promise is no generated workflow business/provider call, not zero infrastructure I/O. If deployment telemetry cannot fit that boundary, the operator must leave the capability unavailable.

Denied implementations include all models/classifier/parameter-extractor, plugin/API/MCP/workflow tools, both Agent implementations, retrieval, document extraction, HITL, remote files and unknown nodes. Deny before model/credential resolution, OAuth refresh, Agent strategy construction, or input/file preparation. There is no live-confirmed mode accepted in this release, even when a caller sends an approval-like value.

## Typed ownership and launch binding

New domain types live in `api/core/dify_builder/execution_policy.py`; service/persistence adapter lives in `api/services/dify_builder/execution_policy_service.py`; workflow capability implementations live in `api/core/workflow/restricted_execution.py`. Avoid workflow importing services: the service validates database ownership and prepares a typed context; native workflow consumes domain types and injected recorder/capabilities.

`BuilderExecutionContext` is a frozen Pydantic v2 model with `extra='forbid'`:

- `policy_version: Literal['builder-restricted-v1']`;
- `request_id`, `tenant_id`, `app_id`, `workflow_id`, `actor_id`, `session_id`, `test_input_id`: nonempty server-owned IDs;
- `execution_revision`, `graph_revision`, `submitted_inputs_digest`, `effective_inputs_digest`, `fixture_digest`, `context_digest`: immutable digests;
- `mode: Literal['restricted', 'mock']` (mock only when a validated node fixture set exists);
- `sandbox_profile: Literal['disabled', 'network-disabled-v1']`;
- typed immutable HTTP fixtures, each with node/version/source/schema binding and text response.

No raw credential material is added. A fixture is a labeled response sample, not an approval. Test-input `source='mock'` alone always produces `mode='restricted'` unless node fixtures actually exist. Optional native context means ordinary non-Builder execution; `DifyWorkflowPort.run_draft` always creates a context and never accepts an option to omit it.

Make `session_id` and `test_input_id` explicit required keywords on the Builder `run_draft` protocol and all Build/Edit/Fix calls. Use the existing saved TestInput owner for fixture lineage: add optional `http_fixtures` to the backend TestInput/submit payload, persist and validate it, and server-stamp its execution revision when the sample is accepted. Store the fixture JSON as an envelope `{schema_version: 1, execution_revision: <server digest>, fixtures: [...]}`; the submit payload contains only the fixture list. At request preparation require the stamped revision to equal the current revision; never restamp an old sample to make it eligible. Existing payloads mean no fixtures. Do not infer fixtures from Start values or synthesize an HTTP 200. Backend ingestion through the existing authenticated test-data action is enough for this slice; record frontend fixture-authoring/display work as unmet, without editing frontend source. Build/Edit/Fix use one shared policy service; fixture support must not depend on route-specific parsing.

A new `DifyBuilderExecutionRequest` row contains ID, tenant/app/workflow/actor/session/test-input owner IDs, immutable policy JSON, `state` (prepared/running/sealed), nullable native Run ID, append-only observation JSON, created/sealed timestamps. A short row-locked transaction appends each observation; no external I/O under the transaction. A sealed row cannot be rewritten. This keeps full observations out of native Run tables and avoids a second executor. New migration creates only this table and optional TestInput fixture JSON; no historical backfill.

The service reconstructs the full session → app → tenant and test-input → session owner chain from DB. It first inspects raw `workflow._environment_variables` and `workflow._conversation_variables` metadata and rejects nonempty environment configuration before invoking `execution_revision`: that existing digest function resolves/decrypts environment values and can access a key provider. Inspect raw app tracing JSON before trace-provider initialization/decryption. Then snapshot graph/config revision and input/fixture digests, perform admission, and create the request. Reject malformed metadata without attempting to resolve it. Accepted contexts flow through an explicit keyword, never `args`, arbitrary `extras`, ContextVars alone, or DEBUGGER inference:

`run_draft → AppGenerateService.generate/_dispatch_generate → WorkflowAppGenerator.generate/WorkflowAppGenerateEntity → _generate_worker → WorkflowAppRunner.run → _init_graph/build_dify_run_context → DifyRunContext → DifyGraphInitContext → DifyNodeFactory`.

Every overloaded generator signature must carry the same optional typed keyword. `DifyRunContext` and `AppGenerateEntity` gain a serializable optional field; `None` is ordinary native execution only. Preserve this field in `model_dump/model_validate` and factory `with_runtime_state`; no live object/callback is serialized in the entity. Pass the row-backed recorder separately when constructing the factory from the runner, or construct an injected recorder in the service-owned worker setup; do not stash mutable recorder state in policy JSON.

**Load-bearing worker gate:** `_generate_worker` rereads Workflow from DB. Revalidate request ownership, native app/workflow IDs, revision, inputs/fixtures, mode, and admission against that actual row and the actual entity **before** environment-secret resolution (including `execution_revision` for a newly nonempty environment config), `_ensure_snippet_start_node_in_worker`, restore/bootstrap, environment variable access and runner construction. A changed graph, feature flag or environment reference must produce unsupported/stale evidence and a published queue error; add the gate inside the worker's caught/published-error region so failure cannot leave SSE waiting forever. Repeat pure binding checks at runner entry and `_init_graph` against the actual graph. The factory compares each constructed node/config to this context and checks supported implementation before any live dependency/model resolution. Use the loaded object consistently after admission; do not reload an unvalidated graph later.

Initial service admission precedes generator file parsing and `TraceQueueManager` construction. Revalidate app external tracing at this boundary and worker boundary. Preserve the existing short DB launch transaction and stream consumption outside the session. Native workflow persistence remains attached and authoritative.

Builder contexts in `AppExecutionParams` must be typed, preserved and explicitly rejected at Celery execution/resume entry before generation. Reject restricted entity resume before trace-manager reconstruction and before native graph restore. This is an unsupported transport, not a silent downgrade. Ordinary payloads remain compatible. All omitted/malformed Builder markers must fail closed at Builder-owned entry points; untrusted HTTP request payloads cannot manufacture the internal context.

## Runtime HTTP enforcement and fixtures

`DifyNodeFactory` chooses restricted collaborators immediately after decoding the typed context; do not run the ordinary eager model/tool/Agent setup for restricted contexts. For each HTTP node inject a distinct `RestrictedHttpClient(context, node_id, recorder)` implementing every Graphon `HttpClientProtocol` method. It has **no underlying live transport**. Missing fixture records `blocked` synchronously and raises a policy error surfaced as a native HTTP node failure. A swallowed observer cannot bypass this boundary.

The adapter receives native-resolved URL, method, headers, params and body from `Executor._do_http_request`. Use that point to record a keyed canonical digest of the request, with a sanitized stable denial code; do not put full URLs, payloads, authorization or credentials into new evidence/error messages. One private fresh server-generated 32-byte HMAC key is created per restricted factory/run and retained identically by with_runtime_state. It stays in memory, never serialized, persisted, logged or client-selected. The diagnostic digest binds the canonical validated resolved request, immutable context, node and per-attempt invocation identity; it is not cross-run reproducible audit or real-call consent. No account/target consent claim is made by this digest. Static admission only explains support and avoids constructors; runtime transport decides fixture/deny.

Release A HTTP admits `authorization=no-auth`, empty headers except explicit text content-type, no file selectors, no multipart/binary bodies, and text/JSON/none bodies. Reject authenticated/credential-bound graphs before native request logging; do not claim that arbitrary user-supplied literals can be automatically classified as secrets. Existing native diagnostic sanitization remains its owner.

A `HttpResponseFixtureV1` has node_id, exact node implementation/version binding, source (`user_sample` or `generated_sample`), schema_version=1, response status 100–599, content_type in `application/json|text/plain`, and UTF-8 body at most 64 KiB. No arbitrary response headers, redirects, cookies, URL rewriting, attachments, functions or file payloads. Validate JSON syntax for application/json. Responses are generated as `HttpResponse(status_code=..., headers={'content-type': ...}, content=body.encode('utf-8'), url=resolved_url)` and flow through real `HttpRequestNode` parsing/output validation. The fixture's digest includes all those fields and the execution revision; no request digest match purports to prove real API behavior. Fixtures are deliberately reusable deterministic samples across native retries, recorded on every actual adapter invocation. Missing/wrong-node/wrong-version/stale/invalid fixtures never become automatic successful stubs.

Deny file-manager/file-reference/tool-file collaborators defensively. Text fixture validation should keep them unreachable; any call records denial and fails. `follow_redirects=True` in Graphon has no effect on this transport because it never dispatches a request. An HTTP effect is never labeled safe based on GET/POST/DELETE, and unknown destructive remote semantics are never authorized. This release simulates only, so it does not need a live endpoint classification.

## Durable provenance and result behavior

Record observations at actual capability boundaries, synchronously before returning fixture output or attempting restricted sandbox RPC. Recorder failure prevents the capability from proceeding. Observations include request/node IDs, kind (`fixture_served`, `effect_blocked`, `sandbox_started`, `sandbox_completed`, `sandbox_failed`), nonsecret reason, implementation version and fixture/profile digest. Native executed node IDs and native terminal outputs still come from real persisted native Run/node evidence. Never fabricate a native workflow_run_id, node success or terminal status.

Finalization requires the same retained recorder and a trusted worker completion snapshot after the existing response close/bounded native join. The actual worker outer-finally passes its real current Thread into a transient one-shot holder; the candidate alone is not completion. Freeze worker_finished only when that captured thread is dead at the one post-close snapshot. Missing/invalid/still-live acknowledgment stays unknown with no later upgrade, no second wait or serialized Thread. Canonical fully owned native Run/node SQL rows, actual persisted graph/effective-user inputs, terminal/chain/retry coverage and reached capability receipts are independently mandatory; frames are presentation only. Incomplete response/worker/recorder/native-row/node/receipt proof yields execution_evidence_unknown first, retaining blocked IDs. Complete persisted failed/stopped/partial-succeeded is native_failed, preserving native status and blocked IDs. Complete native succeeded plus blocked receipts is execution_blocked; complete fixture-backed success is simulation_completed; complete purely scalar native success is restricted_execution_completed and still requires goal/output/revision review. Blocked IDs independently prohibit business diagnosis/repair/publication. A known typed pre-native refusal is the narrow unsupported exception without a fabricated public native ID.

`RunVerification` gains optional execution-evidence reference and summary; `TestResultCard` adds execution_mode, safety_outcome, simulated_node_ids and blocked_node_ids, while retaining actual native status/run ID. Unsupported prelaunch has no native ID and no executed nodes. Keep existing serialized fields compatible and all new summary fields additive; older records decode with unknown provenance, without mutation. A policy denial/unsupported result routes to the existing review/input state with explanation, never the automatic business-code diagnosis/repair loop.

New Builder publication eligibility requires sealed, bound, nonblocked provenance plus existing native status/revision/output checks. Simulation and unknown provenance cannot be used as live verification evidence. A restricted all-native scalar run can pass the execution-safety portion only; no claim of goal acceptance. Existing published versions and historical Run records are untouched. Publishing on simulation-only evidence would require a distinct product contract and is not authorized by this slice.

## Release B: the minimum useful Code/template increment

This follow-on is required to make common deterministic Code workflows useful and must not be lost behind a Start/End demo. Dify owns all required injection points; no Graphon version change is required:

1. Add keyword-only `enable_network: bool = True` to `CodeExecutor.execute_code` and `execute_workflow_code_template`; propagate it into the sandbox JSON. Existing ordinary execution demonstrably keeps True.
2. Add constructor policy to `DefaultWorkflowCodeExecutor` and `CodeExecutorJinja2TemplateRenderer`; restricted factory creates per-run adapters with False. Code goes through native Graphon CodeNode output schema/limits; template goes through native TemplateTransformNode/Jinja adapter. No global patch, subprocess executor, AST/import filter or class replacement.
3. Capability is enabled only by a server-owned `network-disabled-v1` sandbox profile backed by CI conformance for the exact deployed sandbox artifact/config digest. Until then policy service emits `sandbox_capability_unverified`; setting request JSON False alone is insufficient. Add backend config under the existing CodeExecutionSandboxConfig owner; never expose this as `/system-features` permission or let client payload select it.
4. CI tests on the configured sandbox image must prove deterministic Python, JavaScript and Jinja execution, raw TCP and HTTP/HTTPS/DNS/UDP egress denial including proxy env and redirects, no host/other-request filesystem reads/writes, no inherited service secrets, and bounded CPU/time/memory/output. Use local test-controlled egress canaries, not real accounts. Record image digest and restrictive configuration in CI evidence. A language with failed conformance remains disabled independently.
5. Real native positive controls: Start → Code(add 1) → End returns 42 for 41; Start → Template(`Hello {{ name }}`) → End returns `Hello Ada`; invalid output schema fails natively. Unit transport mocks prove forwarding only; they cannot stand in for these CI sandbox controls.

Current compose uses external `langgenius/dify-sandbox:0.2.15` with ENABLE_NETWORK default true. Source inspection confirms request False reaches network seccomp, but complete deployed isolation is unverified. Its unbounded stdout/stderr collector is a concrete blocker for request output budgets, not a reason to pretend network False is ineffective. If it fails, exact required upstream owner is **dify-sandbox `/v1/sandbox/run` execution isolation**, including its Python/Node runners' network namespace/syscall and proxy environment handling. Fix/release/pin a verified sandbox artifact/config before enabling the capability. Graphon does not need to change for this adapter path. The inspected upstream commit is `5631afef06ec88f80c28129aec7fd22a30006b14`; concrete owners include `internal/core/runner/output_capture.go`, service collectors, Python/Node bootstrap/seccomp and dependency/UID-root cleanup. Inspect and fix the exact owner if conformance fails, then release/pin evidence; do not invent a passing artifact. A dedicated verified no-network sandbox endpoint is a deployment alternative; reuse the same Dify CodeExecutor HTTP owner with an explicit per-instance endpoint, never change process-global endpoint state.

## Deferred L2 consent and remaining PRD gaps

No live-call adapter is included. Required next semantics: prepare a sanitized intent after authoritative account/credential resolution without refresh/invoke; explicit user confirmation; durable one-use/bounded grant bound to tenant/app/actor/session, revision, node implementation/provider version, resolved account, target, action, full parameter/input digest, expiry and invocation identity; atomic claim before each runtime effect; permission revalidation; no ambiguous write retries; uncertain outcome reconciliation. Generic test-input/repair/publication approval does not qualify. Changing graph/account/target/params invalidates the grant. Destructive and unknown plugin semantics stay denied even if a generic approval exists.

Remaining product gaps: fixture-authoring UX, model/tool typed fixtures, Chatflow feature guards, files, containers/branches, New Agent policy propagation, real-account consent, and sandbox deployment conformance. Backend records these; frontend source is untouched. The restricted release reduces unsafe execution exposure, but **does not close PRD §9.1 or the common Code workflow acceptance requirement**.

## Binding implementation decisions from preflight

These decisions supersede any less specific draft wording above. They are required backend acceptance, not advisory suggestions.

1. Raw metadata is strictly decoded before ANY execution-path revision/key-provider access, including fixture stamping and postflight binding. Raw fields are `_environment_variables` and `_conversation_variables`; kind is `kind_or_standard`. Malformed/non-object/nonempty configuration refuses launch. Existing unrelated planning reads are outside the narrow execution promise and must not be described as audited. Preserve platform telemetry; restricted per-invocation tracing MUST bypass app-external provider resolution/decryption/dispatch at its independent reload, even on an enablement race.
2. Scalar submitted values are `str | int | float | bool | None`, finite and UTF-8 valid; reject nested/file values even for undeclared inputs. Reuse the existing native scalar normalization owner, extracting its pure validation/sanitization portion if required, then bind BOTH submitted and effective input digests. Defaults, numeric coercion, undeclared-input removal and NUL stripping stay native and idempotent. The same normalized mapping reaches native variable-pool preparation.
3. The immutable admitted node binding is `(node_id, implementation, node_version, normalized_config_digest)`. The config digest is canonical finite UTF-8 JSON of the raw node data with only absent version normalized to `1`; factory checks this raw binding BEFORE concrete-class-owned validation. Resolve raw type/version via the existing native registry; require exact audited class identity/version BEFORE validate_node_data, typed selector/body checks and construction. Explicit `latest`/unknown versions fail, missing version may resolve to audited v1. Trusted platform module import is outside generated graph effects.
4. The row has immutable context JSON/digest, prepared/running/sealed state, claimed native run and task IDs, append-only bounded observations, terminal summary and completion fingerprint. `claim_launch` is exactly once under row lock before worker bootstrap; a generator-allocated UUID is not an observed persisted Run. Revalidation is nonclaiming. Record requires full authoritative context/run/task/node/implementation/fixture/profile binding. Recorder has a monotonic per-request failure latch shared with trusted worker completion, never serialized. Missing completion/receipts or a recovered recorder cannot make a positive seal.
5. Seal reads the actual owned native WorkflowRun and node rows, graph/config/terminal state and required capability receipts. Caller status is not authority. Sealed identical replay is idempotent; conflicting replay and append fail. Native failure is `native_failed`; native success with denial is `execution_blocked`; missing proof is `execution_evidence_unknown`; fixture success is `simulation_completed`; wholly bound native restricted success is `restricted_execution_completed`. SQLite tests are unit controls; production locking/migration races require real PostgreSQL in CI.
6. Shared strict Pydantic test-data decoding happens after authorization, before action processing. All three Build/Edit/Fix handlers receive immutable fixtures and use one port-owned server stamp. Input-only submissions keep their existing revision exemption. Explicit fixture submission requires its `base_app_revision` to match current admitted workflow; absent fixtures are compatible, explicit null/object is invalid. Client fixture provenance is always server-stamped `user_sample`, never `generated_sample`. Do not echo response bodies into generic error/receipt messages. A missing Fix test-input reference returns to test-data input.
7. HTTP fixture fields: frozen extra-forbid schema_version=1; bounded nonempty node_id; node_type=`http-request`; implementation=`graphon.nodes.http_request.node.HttpRequestNode`; node_version=`1`; trusted source; strict integer status 100..599 (bool invalid); content type exactly application/json or text/plain; strict UTF-8 body <=65,536 bytes; JSON finite/syntactically valid. Envelope server-stamps execution revision; sort fixtures by node ID for digest, never graph arrays. Responses use fixed UTF-8 charset. Duplicate/unknown/unused nodes reject.
8. HTTP protocol implements get/head/post/put/delete/patch and both error properties. PolicyTransportError matches request_error ONLY; separate max-retries class prevents native catch from exposing full URLs. OPTIONS unsupported. Runtime kwargs receive an explicit finite/text allowlist; unknown/file arguments deny. Raw and typed auth must both be no-auth with no hidden config. Headers absent or one literal Content-Type in the reviewed application/json/text/plain values, no templates/auth/cookies. Body absent/none/raw-text/json with text BodyData only. Selectors must bind admitted Start/upstream outputs, never env/conversation/files. Reject file fallback defaults too. Supply explicit denying FileManager/FileReferenceFactory/ToolFileManager/factory collaborators; never a missing/falsy HTTP adapter that can fall back live.
9. Typed context propagates through all generator overloads, AppGenerateEntity, AppExecutionParams.new/dump/validate, DifyRunContext/build helper, graph-init context, runner and factory constructor/classmethod/with_runtime_state. Worker reloads App, Workflow and current account/workspace permission before revision/bootstrap; errors publish inside caught queue lifecycle. Restricted root must be admitted Start, call_depth=0, no resume/restored state/single-node/iteration/loop/Celery. Celery marker refusal precedes payload logging; resume refusal immediately follows get_generate_entity before restore/reset/trace.
10. Known prelaunch policy refusal returns a truthful Builder Run with typed summary and no native ID; generic runtime failure remains unknown. Shared typed blocker precedes success/output review/repair diagnosis. Publication reasons extend with execution_policy_blocked, execution_evidence_unknown, simulation_only, execution_provenance_unbound. Guard service release/recovery checks and handler publish, preserving every existing output/revision check and historical data.
11. Release A is Tasks 1–4 PLUS actual composed native scalar/HTTP persistence verification, atomically deployed. Code/template are Tasks 5–6 and remain part of ENG-1183 acceptance. Per-request network False adapters preserve ordinary True. Verified capability must bind actual endpoint/artifact/config/language and current trusted deployment evidence, not client flags or copied digest text. Source inspection alone cannot supply a passing report.
12. Sandbox conformance verifies real Python/JS/Jinja/native output schema, positive egress canaries then restricted zero egress, host/neighbor/secret isolation, serial/parallel cleanup, process isolation and measured CPU/time/memory/PID/stdout/stderr/input/concurrency budgets with healthy recovery. ALLOWED_SYSCALLS override and pre-seccomp preload must be absent/disabled. Immutable dependencies/config and actual deployment identity are required. A dedicated pinned restricted endpoint is permitted; never modify the ordinary shared endpoint as an unreviewed shortcut. Missing/mismatched/stale/failed proof denies RPC. Fix/release the exact sandbox owner when needed; keep parent acceptance open until useful Code/template passes.

## Reviewed Task3 and authoritative Task4 clarifications (2026-10-10)

Task3 was independently accepted through df9fc958c0 after raw numeric overflow and fixed-header consistency regressions. The restricted registry guards original raw config and the actual resolved concrete class before its validator. Only the known native BaseNodeData DTO is adapted with model_dump(mode="json", by_alias=True, exclude_unset=True), preserving exact canonical config/version/extras; no arbitrary serializer or digest waiver. Native HTTP scalar defaults admit exact type/key/value entries with unique body:string UTF-8≤64KiB or finite status_code:number (never bool); oversized integer float conversion refuses with typed sanitized policy error. Objects/arrays/files/default_values alias remain unavailable. Fixed application/json or text/plain, optionally charset=utf-8, uses equivalent case-insensitive admission/runtime literal membership without broader headers/media/auth.

Task4 frozen TrustedExecutionCompletion carries only context, claimed native_run_id/task_id pair or None, strict worker_finished/recorder_healthy/response_completed, worker_exit returned|policy_refused|stopped|failed|not_observed, and typed refusal. No caller status/graph/outputs/executed IDs. The existing transient admission callback on_worker_finished receives actual context/allocated IDs/same recorder/actual current Thread/exit kind after native context and task/session cleanup; allocated preclaim IDs are never public linkage. Capture claim identity before constructing recorder. Synchronize candidate, refusal, claim and the one finalization_closed snapshot without locks across service/SQL/execution. Callback failure/identity conflict invalidates monotonically and preserves the primary native error. Existing300s join is the sole wait owner; dead at the final snapshot proves actual return without claiming the earlier deadline was met.

Seal remains in the existing execution-policy service. Validate complete sidecar owners/context; read canonical owned native Run/node rows and bounded ordered receipts; deterministic fingerprint includes complete/missing evidence facts. Identical replay returns stored summary, conflicting completion/evidence/late native writes cannot upgrade unknown. Do not rewrite native/history/published data or substitute repositories to fake completed evidence. Async persistence with missing rows stays unknown. Stream/callback/setup/close errors finalize unknown where storage permits while preserving primary exceptions/cancellation. Prepared known synchronous refusal and actually returned acknowledged pre-native policy refusal may seal unsupported without fabricated worker completion or native ID.

Composed scalar/HTTP/default-partial native persistence and actual PostgreSQL claim/append/seal/migration controls belong to Task4 before ReleaseA. They execute in CI through the scoped branch workflow, using existing real Flask/request/DB container fixtures and fail-on-call live transport overrides; local integration pytest is not authorized. Root performs separate actual local/Dev E2E and screenshots after reviewed CI/deployment. Task3 SQLite/native harness proves parsing and capability behavior only. ReleaseA is partial; ENG1183 remains open for useful verified Code/template and sandbox conformance.
